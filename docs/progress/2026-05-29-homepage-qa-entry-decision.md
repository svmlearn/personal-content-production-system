# 主页问答入口方向判断记录

日期：2026-05-29
分支：`explore/homepage-qa-entry`
状态：已决策，暂不实现

## 1. 背景

当前个人网站的主页已经有项目轮播和项目详情层，小红书 / 内容获客平台已经作为真实可进入项目存在。它和其他项目的差异是：访问者不只是阅读文字介绍，还可以进入真实系统，看见咨询 Agent、内容工作台和营销内容系统的实际产品入口。

因此产生了一个新的产品判断问题：

> 主页本身是否也应该变成一个问答式对话窗口，用对话来展示 Agent 设计能力，并把访问者引导到不同项目？

## 2. 用户原始诉求

用户最初的想法大致是：

1. 现在小红书平台已经是真实入口，可以真实对话和体验。
2. 但其他项目仍然更多是文字描述，缺少“可互动”的呈现。
3. AI 智能学习伴侣项目本身可以继续保持文字说明，但主页外层也许可以做一个问答式对话体验。
4. 这个问答体验不一定要代表某个具体项目，而是用来展示 Agent / AI 交互设计能力。
5. 用户也意识到：既然小红书项目已经有真实可对话入口，那么主页是否还需要再做一个问答窗口并不确定，所以希望先听判断。

## 3. 当时的反对判断

当时给出的主要反对意见是：

1. 不建议把主页直接改成“纯问答窗口”。
2. 这样容易显得像在作品集外面套了一层 AI 包装，但实际证据反而变弱。
3. 小红书平台已经承担了“我真的做出了一个可运行系统”的证明，如果主页再放一个大聊天框，访问者可能会分不清哪个是真系统、哪个只是展示壳。
4. 主页的核心价值不应从“真实项目入口”滑向“聊天式包装”。
5. 对 AI 智能学习伴侣这类项目，可以展示对话设计、长期记忆、Skill 路由和陪伴产品架构，但不应该在没有真实系统入口时假装它已经是完整可用产品。

当时的结论是：

> 小红书平台承担“我真的做出了系统”的证明；主页问答最多承担“我能把复杂经历讲清楚”的证明。这两个角色不要混。

## 4. 当时提出的替代方案

当时建议如果要做，也不要把主页本体变成聊天机器人，而是做成一个轻量的作品集导航器：

1. 首页保留现有项目 carousel 和真实项目入口。
2. 增加一个 `Ask Yang Labs` / `问我的项目` 之类的轻量入口。
3. 问答只回答作品集相关问题，例如：
   - 哪个项目可以真实体验？
   - 做过哪些 Agent？
   - 小红书平台和 AI 学习伴侣的差异是什么？
   - 哪些项目能证明产品判断能力？
4. 对小红书项目，回答后直接给“进入真实系统”按钮。
5. 对其他项目，回答后跳到对应详情层，而不是制造一个虚假的真实产品入口。

但这个替代方案里曾提到“可以先用静态 / 规则式问答做小原型”。用户随后明确否定了这一点。

## 5. 用户最终决策

用户最终判断：

1. 规则式问答没有意义。
2. 如果只是预设问题和固定答案，它不能真正展示 Agent 能力，反而像低价值交互。
3. 当前主页先保持现状。
4. 本轮不做主页问答窗口，也不做规则式作品集问答层。
5. 先把这次思考过程留痕，方便未来如果重新提起这个方向，直接读取本文件恢复上下文。

## 6. 后续如果重新提起

未来如果重新考虑主页问答入口，不建议从“规则式 FAQ”开始。更合理的重新启动条件是至少满足以下之一：

1. 作品集已经有可调用的真实大模型能力。
2. 问答能读取结构化项目资料，而不是只返回硬编码文案。
3. 问答能明确完成访问者导航，例如根据招聘方、合作方、投资人或潜在客户的关注点推荐项目。
4. 问答能和真实项目入口形成互补，而不是重复小红书平台的对话体验。
5. 问答不会削弱“小红书真实系统入口”作为当前最强作品集证据的地位。

如果只是为了“让主页看起来更 AI”，不要做。

## 7. 当前收口
