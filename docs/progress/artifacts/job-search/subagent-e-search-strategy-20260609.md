## 0. 核心修正

用户最新反馈是正确的：单搜 `大模型产品经理` 会把搜索结果带到金融大模型、语音大模型、数据治理、模型评测、算法策略、车载/机器人等方向。这些岗位标题看似相关，但实际经常要求算法、行业 Know-how 或工程背景，和用户当前最强叙事不完全一致。

下一轮策略应改为：

1. 以 `AI产品经理` 作为主干词捞大池子。
2. 用 `AI Agent`、`智能体`、`AI Native`、`AI应用`、`工作流`、`AI工具/SaaS/平台` 做强相关扩展。
3. `大模型` 只和 `应用`、`Agent`、`工具`、`工作流`、`平台` 组合使用，不再作为单独主搜词。
4. BOSS 推荐流只能作为补充，主采集必须由人工关键词搜索驱动。

## 1. 关键词分层

### A. 主词：必须覆盖

这些词负责把大池子捞起来，适合采集 agent 从列表页大量扫。

| 优先级 | 搜索词 | 用途 |
| --- | --- | --- |
| P0 | `AI产品经理` | 用户意向岗位本名，覆盖面最大，不能跳过。 |
| P0 | `AI 产品经理` | BOSS 分词可能不同，保留带空格版本。 |
| P0 | `AI应用产品经理` | 比 `大模型产品经理` 更靠近应用层产品。 |
| P0 | `AI Native 产品经理` | 已验证高匹配信号，明略样本就是强正例。 |
| P0 | `AI Agent 产品经理` | 第二批高匹配岗位主要来自这个方向。 |
| P1 | `智能体 产品经理` | 中文化表达，可能避开只写 Agent 的重复结果。 |

为什么有效：主词保留召回率，`AI应用/AI Native/AI Agent/智能体` 把搜索重心从“模型本身”拉回“产品化和工作流”，更贴近用户的内容营销系统、Agent 项目、独立原型能力。

### B. 强相关组合词：优先采集

这些词命中率预计高于普通主词，适合第二批或并行 agent 专门跑。

| 优先级 | 搜索词 | 适配原因 |
| --- | --- | --- |
| P0 | `Agent 产品经理` | 覆盖未写 AI 前缀但实际做 Agent 的岗位。 |
| P0 | `AI Agent 工作流 产品经理` | 直接贴合 workflow、tool orchestration、自动化产品。 |
| P0 | `AI工作流 产品经理` | 对应用户 Agent 项目和内容自动化项目。 |
| P0 | `AI工具 产品经理` | 更容易出现 SaaS、效率工具、平台型产品。 |
| P0 | `AI SaaS 产品经理` | ToB 工具/平台场景，通常比硬件和算法更贴。 |
| P1 | `AI平台 产品经理` | 覆盖大模型平台、知识库、企业 AI 平台。 |
| P1 | `大模型应用 产品经理` | 保留大模型方向，但限定为应用层。 |
| P1 | `AIGC 产品经理` | 可能命中内容生成、营销素材、创作者工具。 |
| P1 | `AI营销 产品经理` | 和内容营销系统项目强相关。 |
| P1 | `电商 AI 产品经理` | 用户项目可解释为电商/内容增长/获客工具。 |
| P1 | `跨境电商 AI 产品经理` | Shoplazza、龙品类岗位的来源池，但英语/本地化需降权检查。 |

为什么有效：这些词把“AI 产品”压到用户有作品集证据的方向：Agent、内容、营销、电商增长、SaaS、平台、自动化。比泛搜 `大模型` 更少掉进语音、硬件、金融模型、算法评测。

### C. 探索词：用于扩池，不直接高判

这些词适合在主池不足时扩大样本，采到后需要详情页二次判断。

| 优先级 | 搜索词 | 风险 |
| --- | --- | --- |
| P2 | `内容生成 产品经理 AI` | 可能命中内容平台，也可能偏运营。 |
| P2 | `创作者工具 产品经理 AI` | 可能贴内容生态，但岗位较少。 |
| P2 | `知识库 产品经理 AI` | 可能贴企业 AI，也可能变成 RAG 工程。 |
| P2 | `自动化 产品经理 AI` | 可能贴 Agent workflow，也可能是传统 RPA。 |
| P2 | `生产力工具 产品经理 AI` | 可能出现办公/效率工具，命中率未知。 |
| P2 | `ToB AI 产品经理` | 可能贴 B 端，但领域跨度大。 |
| P2 | `Copilot 产品经理` | 值得搜，但中文 BOSS 岗位量可能少。 |
| P2 | `低代码 AI 产品经理` | 可能贴工具平台，也可能偏实施交付。 |
| P2 | `企业AI 产品经理` | 覆盖企业应用，但容易变成垂直行业解决方案。 |
| P2 | `Prompt 产品经理` | 少见，且可能偏运营/提示词编辑。 |

为什么有效：探索词用来补齐长尾，不适合作为第一轮核心。采集时可以放宽，但初判必须保守。

### D. 慎用词：不作为主采集入口

这些词不是绝对不能搜，而是要么噪声很高，要么已由样本证明容易跑偏。

| 慎用词 | 典型问题 |
| --- | --- |
| `大模型产品经理` | 容易带来金融、评测、策略、算法、语音、车载、机器人。 |
| `大模型策略产品经理` | 往往要求策略算法、推荐/排序、数据分析背景。 |
| `大模型评测产品经理` | 更像评测体系/数据/算法质量岗位，不是用户主叙事。 |
| `RAG 产品经理` | 若是知识库平台可看；若要求 GraphRAG/工程实现则降权。 |
| `数据治理 产品经理` | 已有腾讯样本证明和用户主线弱相关。 |
| `语音大模型 产品经理` | 语音/音频专业门槛高，已有低匹配样本。 |
| `音频 AI 产品经理` | 同上。 |
| `车载大模型 产品经理` | 车载/硬件/语音交互复合门槛。 |

## 2. BOSS 搜索筛选建议

### 城市

主城市：深圳。

扩展城市：广州、杭州、上海、北京。扩展城市只在岗位高度贴合 `AI Agent / AI Native / AI工具 / AI营销 / 电商AI` 时采集。若用户暂不考虑异地，扩展城市只进候选池，不进高优先级投递。

不建议一开始全国无差别扫。全国会提高数量，但会显著增加无效详情页成本。更好的方式是：深圳捞满 60-80 条后，再用强相关词扩展到其他城市。

### 薪资

不要只卡死 `18-30K`。BOSS 的薪资过滤容易漏掉这些情况：

- `15-30K`：实际上符合下限附近。
- `20-40K`、`20-50K`：可能是匹配度高但薪资带更宽。
- `13-23K·15薪`：年包可能接近目标。
- `30-60K`：资深岗位可能超出，但若 Agent/SaaS/电商强相关，可以作为冲刺或参考。

建议采集口径：列表页保留 `15-60K`，初判时标记薪资是否偏低/偏高。真正投递优先看 `15-35K`、`18-35K`、`20-40K` 区间。

### 经验

优先：`1-3年`、`3-5年`、`经验不限`。

谨慎保留：`5-10年`。只有当 JD 极贴 `AI Agent / AI Native / SaaS / 电商内容增长` 且没有明显管理岗要求时保留为 `中` 或 `低`。

列表页可直接排除：`10年以上`、`总监/负责人/合伙人` 且薪资或 JD 显示强管理/技术负责人的岗位。

### 学历

采集阶段不要过度过滤学历。详情页再看是否出现硬性条件：

- `硕士及以上`、`985/211/QS200`、`计算机/人工智能专业强要求`：降一级。
- 如果 JD 同时高度匹配 Agent/工具/内容增长，可保留为 `中`，但不要轻易判 `高`。

### 公司规模与融资阶段

采集阶段不要用公司规模硬筛，否则会漏掉早期 AI Agent 公司。

初判时使用：

- `100-499人`、`500-999人`、`1000-9999人`、`上市/融资中后期`：稳定性加分。
- `20-99人`：中性，看业务和 JD。
- `0-20人`、`未融资`、`成立很短`：只有 JD 高度贴合时保留，通常最高到 `中`，极少给 `高`。
- 匿名猎头：除非 JD 极强且信息足够，否则 `低` 或 `无`。

### 排序

不要只看 BOSS 推荐。每个关键词至少跑两种排序或入口：

1. 综合排序：看平台认为相关的主池。
2. 最新发布：看新岗位，避免推荐流重复和过期。

每个关键词先采前 2-3 页。若某词前两页无效率高于 70%，这个词降级或停止。

## 3. 快速排除规则

### 列表页直接排

看到以下信号，可以不点详情或只做极低优先级记录：

- 岗位名含 `工程师`、`算法`、`开发`、`研发总监`、`技术负责人`，且不是明确产品经理。
- 岗位名含 `语音`、`音频`、`数据治理`、`车载`、`机器人`、`智能硬件`、`IoT`。
- 岗位名含 `实习`、薪资是 `元/天`。
- 经验是 `10年以上`，或 `5-10年` 且标题是总监/专家/负责人。
- 公司明显是硬件/消费电子/医疗器械/穿戴/灯具/音频设备，且岗位标题没有强 Agent/软件平台信号。
- 匿名猎头 + 标题泛泛 + 薪资夸张 + 无公司行业线索。
- Web3/OTC/交易/支付/风控是主标题方向。

### 详情页再排

必须点详情页才能判断的排除点：

- JD 核心是模型训练、算法调参、PyTorch/TensorFlow、RAG/GraphRAG 工程、Python 交付。
- JD 核心是行业专家，如证券基金期货、医疗器械、语音识别、车载座舱、硬件量产。
- 要求候选人承担前后端开发、Java/PHP、架构设计、带研发团队。
- 公司介绍只有宏大叙事，没有明确产品、客户、业务模式。
- 工商信息、地址、福利、公司规模缺失，且不是知名公司公开招聘。
- 0-20 人未融资，同时 JD 写得很虚，如“探索 AI 方向”“寻找合伙人”“从 0 到 1 一起改变行业”。
- 岗位看似 AI，但实际是 SEO、广告投放、运营素材、客服外包、标注管理。

## 4. 初判规则微调

### 高

满足大部分条件才给 `高`：

- 岗位核心是 AI Agent、AI Native、AI 应用、AI 工具、SaaS/PaaS、工作流、知识库、自动化平台。
- JD 强调产品化、0-1、用户场景、PRD、原型、数据指标、迭代，而不是算法工程。
- 业务能自然连接用户作品集：内容营销系统、电商增长、AI 自动化、Agent 项目、AI 编码工具深度使用。
- 公司信息完整，地址/规模/工商/业务能查到。
- 经验要求在 `1-3`、`3-5` 或无硬伤；没有硕士/算法/深行业硬门槛。
- 值得定制简历和项目 pitch。

样本标尺：明略、天裳科技、Shoplazza 这类。

### 中

满足以下任一组合可给 `中`：

- AI 应用方向强，但行业不是最优，如游戏陪伴、金融内容、企业平台。
- 公司好或平台大，但 JD 有一定领域门槛，如搜索推荐、金融、平台技术。
- JD 很贴 Agent/Workflow，但公司早期、规模小、未融资。
- 要求略高，比如资深、英文、跨境、硕士/专业偏好，但不是绝对硬门槛。
- 值得投递和轻度研究，但不一定重写简历。

样本标尺：龙品、Shopee、开源中国、超线性、同花顺、幻境游戏、望船夫。

### 低

以下情况给 `低`：

- AI 只是标题或附属能力，核心仍是传统垂直产品。
- 领域明显有缺口：硬件、语音、搜索、GEO、金融深垂、儿童陪伴机器人、海外本地化强要求。
- JD 有可参考之处，但投递成功率或叙事匹配弱。
- 匿名猎头但 JD 有一点 AI Agent/ToB 信号，暂时保留作备选。
- 经验要求 `5-10年` 或资深偏重，但不是完全不可能。

低不是“垃圾岗位”，而是“不应花定制成本”。

### 无

以下情况直接给 `无`：

- 本质是工程师、算法、研发负责人、架构师、前后端开发。
- 本质是硬件、设备、量产、IoT、机器人、语音音频、数据治理。
- 实习/日薪/兼职/合伙人性质，不符合当前求职主线。
- 匿名岗位信息严重缺失，无法判断真实公司和业务。
- Web3 交易/OTC/支付风控是主线。
- JD 和用户作品集无法建立可信叙事连接。

## 5. 多采集 Agent 分工

下一轮目标不是“每个 agent 找几个”，而是先建 100 条左右候选池，再由初判 agent 统一打标。

### 推荐角色

| Agent | 任务 | 搜索范围 |
| --- | --- | --- |
| A | 主池采集 | `AI产品经理`、`AI 产品经理`，深圳，综合排序和最新发布。 |
| B | Agent 专项 | `AI Agent 产品经理`、`Agent 产品经理`、`智能体 产品经理`、`AI Agent 工作流 产品经理`。 |
| C | 应用/内容/电商专项 | `AI应用产品经理`、`AIGC 产品经理`、`AI营销 产品经理`、`电商 AI 产品经理`、`跨境电商 AI 产品经理`。 |
| D | 工具/平台/SaaS 专项 | `AI工具 产品经理`、`AI SaaS 产品经理`、`AI平台 产品经理`、`知识库 产品经理 AI`、`自动化 产品经理 AI`。 |
| E | 策略审查 | 不采集，检查关键词有效率、噪声来源、规则是否要更新。 |
| F | 合并去重/初判 | 汇总 JSON，按 skill 和偏好画像统一打 `投递意愿`，准备写入飞书。 |

### 防重复规则

所有采集 agent 必须输出到本地文件，不直接写飞书：

- `docs/progress/artifacts/job-search/subagent-a-raw-20260609.jsonl`
- `docs/progress/artifacts/job-search/subagent-b-raw-20260609.jsonl`
- `docs/progress/artifacts/job-search/subagent-c-raw-20260609.jsonl`
- `docs/progress/artifacts/job-search/subagent-d-raw-20260609.jsonl`

每条记录至少包含：

- `source_agent`
- `source_keyword`
- `source_sort`
- `source_page`
- `title`
- `company`
- `salary`
- `city`
- `experience`
- `education`
- `detail_url`
- `normalized_detail_url`
- `company_url`
- `list_tags`
- `quick_reject_reason`

去重顺序：

1. 用 `normalized_detail_url` 去重，去掉 `securityId`、`ka`、时间戳等参数。
2. URL 不同但岗位相同，则用 `公司名称 + 岗位名称 + 薪资 + 城市` 做二级去重。
3. 猎头匿名岗位用 `岗位名称 + 薪资 + 经验 + JD 摘要` 做弱去重。
4. 重复岗位保留 `source_keywords` 数组，记录它被哪些词搜到。被多个强相关词命中的岗位可加一点优先级。

### 采集节奏

第一轮：

- A/B/C/D 每个 agent 目标列表候选 40-60 条。
- 每个 agent 只打开通过列表页快筛的详情页，目标详情页 25-35 条。
- 合并后预期得到 80-120 条去重候选。

第二轮：

- F 统一初判。
- E 统计每个关键词的有效率：`高+中` 占比、`无` 占比、匿名占比、硬件/算法噪声占比。
- 对有效率低的词停用，对高命中词扩页或扩城市。
