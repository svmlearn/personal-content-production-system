# 打招呼术语证据库 / 2026-06-10

用途：为飞书 `岗位池` 的 `打招呼术语` 字段提供可复用口径。原则是先保证事实准确，再追求 IM 开头吸引力。

## 硬规则

- 不再直接写 `网站里放了...`，除非该内容确实在公开作品集页面可见。
- 公开作品集可见内容、简历经历、用户补充口径、内部术语必须分开。
- 招聘方不认识的项目名或内部名，要翻译成岗位能理解的能力或场景。
- 低匹配风险不写进发给招聘者的话术，仍放在 `初判状态`。

## 已确认口径

### AI 教育 / 智蛙面试

适用岗位：教育 AI、AI 批改、题库、学习产品、教研工具、面试/考试训练、学习伴侣、知识服务类岗位。

可说事实：

- 个人网站里有 AI 教育相关项目：智蛙面试。
- 智蛙面试经历包括从 0 到 1 搭建产品模块。
- 做过数据体系搭建。
- 做过 good case / bad case 定义。
- 做过大量用户调研、用户访谈，并访谈专业老师，提取老师批改一份申论的完整流程，再把流程转成 AI 工作流。
- 设计过一整套 Dify 从搭建、撰写、改写、跑测试、和测试数据集对比、再优化的评测优化流程，并把流程沉淀为 skill。
- 智蛙方向可强调 AI 教育产品、申论批改、题库/批改流程、数据指标、用户反馈驱动迭代。

可用表达草稿：

> 这是我的作品集网站，有 AI 教育项目：https://2young.xin/ 你好，我是洋。我做过智蛙面试的申论/面试 AI 产品模块，经过用户访谈和专业老师访谈，把老师批改申论的流程拆成 AI 工作流，并搭过数据指标、good case / bad case 和 Dify 评测优化 skill。

### 硬件 / ToB 定向音响

已确认：

- ToB 定向音响、扫码用机、线上内容管理基本不用写。
- 如果不投硬件类产品，不要写。
- 即使投硬件岗位，也不建议写 `ToB 硬件 MVP 经历`，容易把实习经历夸大。

## 明确不能再这么写

- `里面放了 ToB 定向音响 MVP、扫码用机、内容管理...`
  - 原因：这些主要在简历里，不一定在公开作品集网站里展示；用户确认打招呼里基本不用写，也不要把实习经历夸大成硬件 MVP。
- `里面放了 KeploreAI Agent...`
  - 原因：KeploreAI 是公司名 / 项目背景，招聘方不知道含义，裸写像黑话。
- `里面放了 Codex Agent Harness...`
  - 原因：内部能力证明需要翻译成 `熟练使用 Codex / Claude Code、理解 Harness Engineering、会做 skill/工作流编排`。

## 仍需谨慎的内容

1. `AI 剪辑` 不作为默认主卖点，除非岗位明确要求视频生产链路。
2. `KeploreAI` 可以写，但必须解释业务场景，不能裸写 `KeploreAI Agent`。
3. `Codex Agent Harness` 不能裸写，必须翻译为 Codex / Claude Code、Harness Engineering、skill、sub-agent 协作、验收流程等能力。
