## 不建议作为长期主版本的方向

### C端 AI 产品经理

当前 JD 样本里没有形成足够强的“C端通用产品经理”经历簇。多数中高岗位更强调：

- AI 应用落地。
- Agent / 工作流。
- B端/SaaS/商家/企业服务。
- AIGC 内容/增长。
- 数据指标/评估。

所以 C端不应单独做长期版本。遇到 C端岗位时，从 V1 或 V2 临时改：

- 强化用户体验、用户调研、留存/转化、Aha Moment。
- 用 KeploreAI、AI 学习伴侣、智蛙用户路径做证据。

### AI 教育版

教育/题库/批改经历簇只有 5/66。它不是当前目标池的主版本，但用户自身证据很强，可以作为专项投递版本。

使用条件：

- JD 明确写教育、学习产品、题库、批改、教研、考试、陪伴学习。
- 或者公司明显是教育科技。

### 零售 / 门店版

零售/门店只有 7/66，但喜茶等高价值岗位需要定制。

使用条件：

- JD 明确写零售、门店、智能点单、巡店、排班、库存、本地生活。

写法：

- 不要假装有门店项目。
- 用 AI 内容营销系统的业务流程拆解、权限控制、任务流、人工审批，去匹配“AI 落到一线业务流程”。

### 金融 / 数据治理版

金融/银行/风控/数据治理命中 11/66，但高意向只有 1 条。多数是中或低，不建议单独维护主版本。

写法：

- 不要包装成金融专家。
- 只写业务系统、数据分析、AI应用产品化、流程/指标/工作流。

## 对现有简历的直接影响

现有简历应先改成 V1 主投版，而不是平均展示所有经历。

必须改：

1. 首页 Profile 要把 `AI应用 / Agent / 工作流 / 0-1 / 数据评估` 写得更像 JD 关键词。
2. 第一屏的 `Codex Agent Harness` 要翻译为 `Codex / Claude Code + Harness Engineering + skill/sub-agent/验收流程`，不能当黑话放在那里。
3. AI 内容营销系统要从“个人项目说明”升级为简历主项目之一，明确写：
   - 0-1 搭建营销 Agent。
   - 上下文工程。
   - 工具调用。
   - 意图识别。
   - 权限控制。
   - 产品原型。
   - 客户需求沟通。
4. 智蛙要补上用户确认的经历关键词：
   - 用户访谈。
   - 专业老师访谈。
   - 批改流程抽取。
   - AI 工作流。
   - 数据指标。
   - good case / bad case。
   - Dify 评测优化 skill。
5. 实习硬件经历在主投版中压缩，不再强调 ToB 硬件 MVP。

## 推荐执行顺序

1. 先做 V1 主投版：AI 应用 / Agent / ToB SaaS 通用版。
2. 从 V1 派生 V2：AI 营销 / AIGC / 电商增长版。
3. 再派生 V3：技术理解型 / AI Coding / 开发者工具版。
4. V4 企业 AI / RAG / FDE 版等有明确投递对象时再做。
5. 教育、零售、金融不作为长期主版本，只做专项插拔模块。
