## 3. 每个版本怎么改同一段经历

### AI 内容营销系统

共同事实：

- 从 0 到 1 搭建 AI 内容营销系统。
- 自己做营销 Agent 框架。
- 覆盖上下文工程、工具调用、意图识别、权限控制。
- 自己做产品原型、客户沟通、需求挖掘。

V1 Agent / AI Native 版：

- 强调 Agent 框架、上下文工程、工具调用、权限控制、任务状态、人工审批、失败重试。
- 少写“内容营销”，多写“把业务流程拆成 Agent 工作流”。

示例 bullet：

> 从 0 到 1 搭建 AI 内容营销 Agent，将产品定位、目标人群、素材上下文、历史反馈和生成任务组织成可运行的 Agent 工作流；负责意图识别、上下文工程、工具调用、权限控制、任务状态和人工审批流程设计。

V2 AI 营销 / AIGC 版：

- 强调营销 Agent、内容生产、热点/素材/营销日历、图文/视频脚本、客户需求沟通。
- 这是该版本的第一主项目。

示例 bullet：

> 从 0 到 1 设计 AI 内容营销系统，通过咨询式营销 Agent 追问产品、人群、卖点和账号风格，沉淀品牌定位上下文，并串联热点选题、营销日历、图文生成和视频脚本生产，服务内容增长和获客场景。

V3 技术理解型 / AI Coding 版：

- 强调自己写 Agent 框架、工具调用、权限、Runtime、Harness、用 AI coding 做原型。
- 不要变成工程师简历，重点是“技术理解支撑产品决策和原型验证”。

示例 bullet：

> 基于 AI coding 自建内容营销 Agent 原型，设计 Agent 意图识别、上下文压缩、工具调用、权限控制和任务验收流程，用可运行 Demo 验证产品流程，而不是只停留在 PRD。

V4 ToB / SaaS / FDE 版：

- 强调业务流程 AI 化、客户需求挖掘、权限/审批/任务状态、可交付系统。

示例 bullet：

> 面向真实商家内容生产场景，将客户需求拆解为品牌定位、素材管理、营销日历、内容生成、人工审批和版本记录等业务流程，并用 Agent 工作流和权限控制把 AI 能力嵌入到可交付系统中。

V5 AI 教育版：

- 不是主项目，只作为“AI 工作流和 Agent 能力可迁移”的佐证。

### 智蛙面试

共同事实：

- AI 教育产品。
- 做过申论/面试 AI 产品模块。

- 强调教育场景、专业老师批改流程、用户反馈、评测优化。

示例 bullet：

> 通过用户访谈和专业老师访谈，拆解老师批改一份申论的完整流程，将标注、打勾、评分、评语风格和结构化报告转化为 AI 批改工作流，并通过 good case / bad case、测试数据集对比和 Dify 评测优化流程持续迭代。

V1 Agent / AI Native 版：

- 强调 AI 工作流、产品模块 0-1、指标、评测。

## 4. 版本的首页 Profile 建议

### V1 Agent / AI Native 默认版

> AI 产品经理 / AI Product Builder，擅长把业务场景拆解为 Agent 工作流、工具调用、上下文工程和可验证原型。做过 AI 内容营销系统、KeploreAI Agent 产品、AI 学习伴侣和 AI 教育产品模块，能从用户需求、产品规划、AI 原型、指标评估到迭代落地完整推进。

### V2 AI 营销 / AIGC 版

> AI 营销 / AIGC 产品经理，擅长把品牌定位、用户画像、素材上下文和内容生产流程产品化。曾从 0 到 1 搭建 AI 内容营销系统，设计营销 Agent、内容工作流、权限控制和客户需求沟通流程，也有教育产品增长与用户转化指标经验。

### V3 技术理解型 / AI Coding 版

> 技术理解型 AI 产品经理，深度使用 Codex / Claude Code 做产品原型和工程协作，理解 Harness Engineering、skill、sub-agent 协作、工具调用顺序和验收流程。能把 Agent / AI coding 从“能跑”推进到可控、可评估、可交付的产品流程。

### V4 ToB / SaaS / FDE 版

> ToB / 企业 AI 产品经理，擅长从业务流程和客户需求出发，设计 AI 工作流、权限审批、任务状态、知识/上下文结构和可交付原型。做过 AI 内容营销系统、AI 学习伴侣、企业 AI 赋能样例和 AI 教育内部流程改造，能把大模型能力落到具体岗位和业务流程中。

### V5 AI 教育 / 学习产品版

> AI 教育产品经理，做过智蛙面试申论/面试 AI 产品模块和 AI 学习伴侣。擅长通过用户访谈、专业老师访谈和测试数据集，把教学/批改/咨询服务拆成 AI 工作流、评测优化流程和长期记忆/Agent 产品体验。

## 5. 当前简历最需要改的地方

1. 当前第一页偏炫技和抽象，`Agent 工作系统` 容易让非技术招聘者看不懂。不同版本需要换成更贴岗位的 Profile 和项目摘要。
2. `Codex Agent Harness` 需要翻译成能力，不应作为招聘方默认理解的名词。
3. AI 内容营销系统目前可以再产品化：客户需求、营销 Agent、权限控制、上下文工程、工具调用、产品原型要写得更像岗位 JD。
4. 智蛙需要加入用户补充的关键证据：大量用户访谈、专业老师访谈、老师批改流程抽取、Dify 评测优化 skill。
5. 实习硬件经历应该在多数版本里压缩，甚至只留很短一行，不要抢主线。

## 6. 推荐执行顺序

1. 先做 `母版素材库`：把每段经历拆成不同叙事 bullet，不考虑版式。
2. 再做 V1 `Agent / AI Native 默认版`，作为主投递简历。
3. 再从 V1 派生 V2 `AI 营销 / AIGC 版` 和 V3 `技术理解型 / AI Coding 版`。
4. 如果喜茶、FDE、企业服务类继续增多，再做 V4 `ToB / SaaS / FDE 版`。
5. AI 教育岗位不是当前主搜索方向，但智蛙和学习伴侣证据强，保留 V5 作为特定岗位投递版本。
