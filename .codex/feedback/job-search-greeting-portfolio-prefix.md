## Signal

用户指出 BOSS 打招呼话术里 `AI营销作品集在这`、`Agent作品集在这`、`门店AI作品集在这`、`作品集在这，有Agent项目` 这类开头语感生硬。真实表达应是个人网站 / 作品集网站，里面包含某些相关项目，而不是把网站临时命名成一个 JD 关键词专题。

后续用户进一步指出：不能把简历里出现过、内部理解过、或并未在网站展示的内容写成 `里面放了...`。例如 `KeploreAI Agent` 对招聘方是不明所以的黑话，`Codex Agent Harness` 应翻译成 Codex / Claude Code、Harness Engineering、skill、sub-agent 协作和验收流程能力；ToB 定向音响 / 扫码用机这类实习经历不要默认写进打招呼。

## Better Rule

写 `打招呼术语` 时，使用自然的人类表达，例如 `这是我的作品集网站，有Agent项目：https://2young.xin/`、`这是我的作品集网站，有内容营销系统：https://2young.xin/`、`这是我的作品集网站，有AI落地项目：https://2young.xin/`。

不要使用 `Agent作品集`、`AI营销作品集`、`AI Coding作品集`、`门店AI作品集`、`作品集在这` 这类硬造标签。相关性应在后文说明，例如 `里面放了 KeploreAI Agent...` 或 `里面放了 AI 内容营销系统...`。

还要区分“作品集网站实际展示了什么”和“简历或真实经历里有什么”。只有确认公开作品集页面里能看到的项目，才可以写 `网站里/里面放了...`；如果只是简历经历或内部项目，应用 `我做过...`、`简历里有...`，或者先列出来让用户确认，不能假装它已经在作品集网站里展示。

已确认的更具体口径：

- 智蛙面试：强调用户访谈、专业老师访谈、提取老师批改申论流程、转成 AI 工作流、数据指标、good case / bad case、Dify 搭建-测试-优化评测流程并沉淀为 skill。
- AI 学习伴侣：强调社群老师服务产品化、商业咨询、职业规划、日常陪伴、上下文工程、意图识别、记忆模块和 Agent 产品性能测试。
- AI 内容营销系统：强调 AI 营销、0-1 营销 Agent、Agent 产品设计、上下文工程、工具调用、意图识别、权限控制、产品原型和客户需求沟通。
- KeploreAI：可提公司名，但必须解释为面向 AI 算法工程师项目复现/部署场景的 Agent 产品经历。
- Harness Engineering：可以直接写英文。
