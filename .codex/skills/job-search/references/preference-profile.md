# Preference Profile

This profile captures the user's current AI product job preferences as of 2026-06-09. Treat it as a living heuristic, not a permanent rule. Update it when the user gives new feedback.

## Target Positioning

The user is strongest for AI application product roles where product work, AI tool fluency, and end-to-end delivery matter more than formal algorithm engineering.

Best narrative:

- Built and can explain real AI/Agent projects.
- Can prototype, write PRDs, reason through workflows, and use AI coding tools deeply.
- Can connect AI to content marketing, ecommerce growth, automation, knowledge work, and practical product scenarios.
- Has product sense and independent builder credibility, not just "prompt user" credibility.

## Best-Fit Role Archetypes

### High Fit

- AI Native 产品经理.
- AI Agent 产品经理.
- 大模型应用产品经理.
- AI 工具 / SaaS / PaaS / 工作流平台.
- 大模型托管平台、开发者平台、知识库、自动化平台.
- AI 内容营销、电商增长、创作者工具、运营提效工具.

### Medium Fit

- 电商 + AI 搜索/推荐/内容生成 when the JD can be connected to the user's AI marketing/content project.
- Larger-company AI product roles where the exact domain is imperfect but the JD values application-layer product thinking.
- AI platform roles needing some technical fluency but not hands-on algorithm/model engineering.

### Low Fit

- Famous company but JD requires a domain the user lacks, such as community search, voice data governance, GEO, or hardware.
- Jobs that are possible to apply to but should not receive heavy customization.
- Roles where "AI" is present but the core work is traditional vertical product management.

### No Fit

- Hardware/IoT/consumer electronics-first roles where AI is embedded into devices and the product core is hardware experience, supply chain, or device interaction.
- Algorithm/engineering-heavy jobs requiring model training, deep ML frameworks, RAG/GraphRAG engineering, or production AI engineer responsibilities.
- Voice/audio/data governance roles with strong domain requirements.
- Anonymous headhunter roles with serious information gaps.
- Very early tiny startups with unclear product/business unless the user explicitly wants riskier exploratory options.

## 投递意愿 Mapping

Use these labels:

- `高`: Strong story match; user should customize resume/project pitch.
- `中`: Plausible match; apply and do light research.
- `低`: Backup or casual apply; little customization.
- `无`: Do not prioritize; keep only as record unless user overrides.

Prefer not to over-rank. A famous company with a poor JD fit should often be `低`, not `高`.

## Red Flags In JD

Mark down when JD emphasizes:

- "熟悉 TensorFlow / PyTorch / 机器学习算法 / 模型训练".
- "RAG / GraphRAG / 数据管道 / Python 工程" as hands-on delivery.
- "语音识别 / 音频处理 / 数据治理 / 标注体系" as core domain.
- "智能硬件 / 穿戴 / 灯光 / IoT / 家具家居 / 消费电子" as the main product.
- "海外本地化 / 英语强要求 / 美国用户深度经验" when it is mandatory.
- "业务尚未跑通", "探索方向", "0-20人", newly founded company, unclear product.

## Green Flags In JD

Mark up when JD emphasizes:

- Productizing LLM capabilities into real user workflows.
- Agent workflow, tool orchestration, knowledge base, automation.
- 0-to-1 product ownership with real users.
- AI coding tools as a product manager advantage.
- Product taste, prototyping, user feedback, metrics, iteration.
- User-facing or platform products where the user's project experience can be explained naturally.
